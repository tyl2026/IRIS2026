# AI 需求生成 Skill

将 HIS 页面优化内容或对话中描述的功能改动，按"面向非信息专业医护人员"的标准，
拆分为结构化的 AI 需求文档。

## 输入来源

两种方式可单独使用或结合使用：

1. **代码对比分析**：比较 `HISUI-优化/00原文件/` 与 `HISUI-优化/01优化中/` 中同一模块的文件差异
2. **对话内容提取**：直接分析用户在对话中描述的功能需求和改动

## 输出规范

### 文件命名

```
NNN_YYYYMMDD_模块名称_AI需求.txt
```

- 序号：3位数字 `001`/`002`/`003`，按生成顺序递增，便于文件排序
- 日期格式：`YYYYMMDD`（如 `20260703`）
- 新需求生成时自动取当前目录最大序号+1

### 文件保存路径

1. 检查是否存在 `项目根目录/AI需求\` 目录
2. 若不存在，询问用户是否指定目录
3. 用户不指定时，默认使用 `%USERPROFILE%\Desktop\AI需求\`（桌面）

```
项目根目录/AI需求\    （优先）
%USERPROFILE%\Desktop\AI需求\   （桌面兜底）
```

### 需求配图

需求配图存放于 `项目根目录/AI需求\需求附件\`，按序号对应需求：

```
需求附件/1-1.png → 001_xxx_AI需求.txt 中的需求1
需求附件/1-2.png → 001_xxx_AI需求.txt 中的需求2
需求附件/2-1.png → 002_xxx_AI需求.txt 中的需求1
需求附件/2.png   → 002_xxx_AI需求.txt（整文件共用，fallback）
```

提交时自动读取对应图片 → base64 → 内联到需求内容的 `[备注]` 中，不作为附件上传。

## 模块匹配

`assets/模块清单.txt`（skill 内置）是全院产品模块字典（标准数据，只读不可修改）。

生成需求前，必须先读取模块清单，按以下规则匹配模块：

1. 用页面名称或菜单名称在模块清单中查找匹配行（模糊匹配产品模块列）
2. 匹配到的，取该行的「产品模块」作为模块名称，「产品线」和「所属组」作为补充信息
3. 未匹配到的，列出最接近的候选项让用户确认，不得自行新增模块
4. 模块清单为标准字典，任何时候不得修改其内容

### 内容格式

每条需求严格按以下模板输出：

```
需求N：[AI需求]页面名称 — 功能简述
模块：XXX
产品线：XXX
产品组：XXX
现状： ...
需求： ...

需求N+1：[AI需求]页面名称 — 功能简述
...
```

> 同一需求内的字段之间无空行；不同需求之间用空行分隔。

## 拆分规则

### 原则
- 将一个完整功能按操作步骤拆分为多个独立需求，每条需求只做一件事
- 面向医院非信息专业的医护人员，禁止使用技术术语（如 Global、TSV、后端、前端、CLS、JS 等）
- 每个需求必须包含两要素：现状、需求

### 现状
- 格式：在XX页面/界面做XX操作时，原来有什么问题或不方便的地方。安全组：XX，科室：XX，菜单：XX。
- 先说清楚在哪个页面做什么操作，再说问题，最后附使用环境信息
- 1-2 句话，口语化

### 需求
- 描述希望实现的功能，从"使用者能看到什么、能做什么"的角度写
- 默认不超过 50 个汉字，最多不超过 100 个汉字

### 需求数量
- 无硬性限制，按操作步骤自然拆分
- 如果一个功能包含多个独立操作（如：下载模板 → 选择文件 → 预览 → 导入），拆为多个需求
- 如果多个操作紧密耦合不可拆分，可合并为一条

## 需求总表

除每条需求的独立 TXT 外，额外维护一个需求总表文件：

**文件名**：`需求总表.txt`

**追加规则**：需求总表是累积文件，新生成的需求必须追加到现有内容之后，不可替换或覆盖已有内容。生成前先读取现有文件，在末尾追加新需求条目。

**内容格式**：

```
模块名称：XXX
生成日期：YYYY年MM月DD日
需求总数：N 条

需求1：[AI需求]XXX — XXX
需求2：[AI需求]XXX — XXX
...

模块名称：YYY
生成日期：YYYY年MM月DD日
需求总数：M 条

需求1：[AI需求]YYY — XXX
需求2：[AI需求]YYY — XXX
...
```

## 工作流程

1. **确定输入**：确认用户要分析的模块名称，定位原文件与优化文件路径
2. **分析差异**：对比代码或提取对话中的功能描述，列出所有改动点
3. **匹配模块**：读取模块清单.txt，用页面名称匹配产品模块、产品线、所属组
4. **拆分需求**：按操作步骤将改动拆分为独立需求，确保每条只做一件事
5. **撰写内容**：按模板格式撰写，全程使用非技术语言
6. **检查长度**：逐条检查需求目标字数，确保默认 ≤50 字、最多 ≤100 字
7. **生成文件**：输出需求 TXT 到指定目录，读取现有需求总表后追加新条目
8. **告知用户**：列出生成的文件路径和需求概要
9. **提示提交**：生成完成后询问用户"是否提交需求到协同网？"，确认后执行提交脚本

## 提交到协同网

需求生成后，可自动提交到协同网需求创建页面。

### 提交脚本

```
python scripts/submit_ai_requirement.py
```

### 提交流程

1. 自动选取序号最小且未标记 `_已提交` 的需求文件
2. 打开 Chromium 浏览器 → 用户扫码登录 → 自动逐条填写提交
3. 每条需求自动匹配附件（`需求附件/N.png` → `NNN_xxx_AI需求.txt`）
4. 提交完成后自动重命名为 `_已提交` 标记，下次跳过

### 提交参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 需求类型 | 新项开发 | 下拉选择 |
| 接收人员类型 | 本组人员 | radio 选择 |
| 接收人 | 谭有良 | 按姓名检索选中 |

## 示例

输入：特殊患者管理模块优化（批量导入 + 类型判断），模块清单匹配「门诊医生工作站 / 门诊医生工作站 / 医生站」

输出（`20260703_特殊患者管理_AI需求.txt`）：

```
需求1：[AI需求]特殊患者管理 — 下载导入模板
模块：门诊医生工作站
产品线：门诊医生工作站
产品组：医生站
现状： 批量导入前需要按固定格式填写患者信息，没有模板容易填错格式导致导入失败。安全组：有权限的安全组，科室：信息科、医务科，菜单：特殊患者管理。
需求： 页面上增加「下载模板」按钮，点击后下载含姓名、身份证号、患者类型等表头的标准 Excel 空白表格。

需求2：[AI需求]特殊患者管理 — Excel 文件选择与预览
模块：门诊医生工作站
产品线：门诊医生工作站
产品组：医生站
现状： 用户选择文件后需要先确认内容是否正确，避免选错文件导入错误数据。安全组：有权限的安全组，科室：信息科、医务科，菜单：特殊患者管理。
需求： 增加「导入」按钮弹出对话框，支持选择 Excel 文件，选好后在页面表格中预览前几行数据供用户确认。

需求3：[AI需求]特殊患者管理 — 批量导入与结果反馈
模块：门诊医生工作站
产品线：门诊医生工作站
产品组：医生站
现状： 手动逐条新增效率低，希望系统自动读取 Excel 内容批量录入，并告知导入结果。安全组：有权限的安全组，科室：信息科、医务科，菜单：特殊患者管理。
需求： 确认导入后系统自动逐条录入，缺失必填项的行跳过，完成后显示成功、跳过数量及失败原因，列表自动刷新。

需求4：[AI需求]特殊患者管理 — 患者类型自动判断
模块：门诊医生工作站
产品线：门诊医生工作站
产品组：医生站
现状： 挂号收费时需知道患者是不是院内职工等特殊类型，现在查起来麻烦。安全组：N/A，科室：全院，菜单：N/A。
需求： 系统根据患者信息自动判断是否属于某特殊类型，直接返回"是"或"不是"，不在名单或已过期返回"不是"。
```
